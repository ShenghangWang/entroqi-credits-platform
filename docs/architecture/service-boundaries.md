# Shared Credits architecture ownership

24 October 2026. Canonical financial implementation contract. Product-wide intent and delivery queue: [simulation decision 0016](https://github.com/ShenghangWang/ai-native-simulation-platform/blob/main/docs/decisions/0016-shared-billing-ownership-and-lifecycle.md) and [commercial queue](https://github.com/ShenghangWang/ai-native-simulation-platform/blob/main/docs/commercial/billing-delivery.md).

Keep one shared MySQL financial core and one private API; product applications own their authentication/session stores and feature enforcement. Credits owns wallet/ledger, immutable price/order snapshots, provider verification, exact credit/currency arithmetic, holds/actual settlement and generic paid entitlements. Product-specific offers are application-scoped configuration. Browser requests cannot set prices, balances, payer IDs or privileged roles. Product backends never write financial tables directly. No universal subscription framework, central-login replacement or per-product fork is required.

Financial lifecycle is distinct from login identity. Phone/email/username are reusable contacts, never primary keys or wallet ownership proof. Closure retains IDs/financial history, releases contacts and prevents resurrection through the old issuer/subject. Return requires new verification and subject. Refuse closure while funds, holds, unsettled payment/organization/agent relationships require reconciliation. Suspension keeps contacts; do not equate it with closure. Product-session revocation/deletion is coordinated by the product through an idempotent close call; failure must remain retryable and cannot report completed deletion.

Prefer additive migrations. One personal wallet per user/currency and one organization wallet per tenant/currency are database constraints. Preflight legacy duplicates before migration; never silently merge balances. Extract identity SQL from HTTP into one customer service. Preserve existing ledger core; remove accidental negative/oversized money mutations and support settle-actual/release-remainder. Legacy agent/car seed code stays unmounted and outside the new product's live route; do not run car-specific seeds in a shared production catalog.

Public payment callbacks/query responses must prove signature, merchant/app/order/amount/currency and repeat safety before changing money. Provider I/O must be bounded and must ultimately use durable outside-transaction dispatch/reconciliation. Existing callback/core tests are not live merchant/refund evidence. Cash refunds, hold release and post-settlement ledger adjustments are different operations. Keep paid APIs disabled until their dedicated gates pass.
