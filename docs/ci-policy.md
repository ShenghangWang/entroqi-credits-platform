# Credits CI and verification policy

Organized12 November 2026. Credits backend and original console source are public by owner authorization; operations/credentials and other products' source stay private. This file owns verification scope/cost controls, not product status or activation. [Current source/policy map](current-state-and-policy-map.md) owns those distinctions; the [former October guide](history/ci-policy-through-2026-10-27.md) preserves dated source/allowance context.

## Match checks to changes

For proven guidance-only changes compare runtime, dependency/lock, schema/financial policy, enabled configuration and harness inputs with the qualified baseline; check Markdown/navigation, authority/status consistency, historical prose and preserved progress. Reuse the dated matching runtime evidence rather than repeating unchanged type/unit/MySQL/browser/container jobs. A documentation-only descendant must not be described as tested by an older runtime run.

After those bounded checks, a guidance-only commit or merge may use `[skip ci]` to avoid unchanged automatic runtime jobs. This changes no workflow/check surface and supplies no runtime/release acceptance. Never apply this to canonical source/content, config, dependencies, migrations, financial/acceptance semantics or an unresolved failure. If protected-branch requirements demand a check, satisfy them through the normal procedure; do not weaken controls.

Changed runtime/service/console/policy/dependencies/schema and actual release qualification retain all existing checks: production audits for backend/console, types/lint/unit tests, both builds, real MySQL integration, repeated migrations, actual original pricing/owner browsers, Compose validation, Docker packaging and source/history scanning. Use the existing workflow and committed locks; do not remove checks or start a duplicate/scheduled suite. Run DB fixture jobs sequentially against a named disposable schema, never production/company/former-employer data. Missing local services are a recorded limitation, not a passing result. Inspect failures before one evidence-backed transient retry; deterministic failures require a fix.

## Source, allowance and release controls

Batch scoped changes, freeze the tested source, verify remote head/check identity and retain actual artifacts/limitations. A skipped/canceled/failed run, cached dependency or local build is not live release evidence. Actual merchant/refund, owner recovery/sender, private host/data/monitoring and clean off-host restore remain separate gates.

Account-wide CI usage/budgets are operator-controlled and may include private repositories. Verify current included allowance before substantial required runner use; dated October/November figures are not current billing. At75% review projections; at90% reserve capacity for required verification and pause optional work. No automatic paid runner/upgrade, budget/payment/visibility/scope change, external CI or scheduled monitor is authorized here. Unknown near-exhaustion capacity is not assumed free; continue independent local work and retain the actual release gate until the owner supplies a permitted limit. No private source or financial account details should be copied into public CI/documentation.
