## Owner workflow and boundaries

Open **所有者与操作记录** or the dashboard's **创建公司所有者** button. Choose the partner's distinct login ID and display name; generate and privately save its separate random credential. Enter the current owner's credential, record a reason, check the highest-permission confirmation and submit. The existing owner keeps its login. The partner logs into the same back office using the new ID/credential. No partner account has been created in the live installation by this implementation; only disposable tests create sample identities.

The log distinguishes saved drafts from published prices and confirmed plan withdrawal; it shows each actor, time, period, before/after amount/availability/trial and reason. Filter by owner and page through the records. Existing historical price rows appear through their original transactional history. Earlier security events remain in the protected legacy JSONL operational log; the new durable security-event feed starts with this source. Audit records cannot be edited/deleted through the API. There is no owner delete/demotion endpoint, so this change cannot remove the last owner.

The protected file currently supports at most16staff accounts. Creation uses a durable idempotency receipt; reuse of a key for different details is refused. The audit outbox is bounded to64events and fails closed if SQL cannot be restored before capacity runs out. Back up the complete protected staff file (including pending events/receipts), its legacy operational log and MySQL `staff_audit_events` plus pricing history. Retain original immutable IDs across restores. Do not independently restore a stale staff file and financial audit DB without reconciliation. Keep production TLS/origin restrictions, private directory ownership and off-host log access/retention/monitoring; local tests are not tamper-proof external logging.

Owner email recovery remains bound to the originally enrolled owner. Adding another owner never silently shares that owner's recovery email/offline factor. Each new owner can use the existing authorized server-administrator credential recovery command; per-owner email enrollment is a separate future enhancement. The existing staged original recovery enrollment is preserved.
