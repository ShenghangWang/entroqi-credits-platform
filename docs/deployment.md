## Private pricing and expense console

Apply migration000012 after a stopped backup, with the existing repeated-migration checks. Configure `CREDITS_PRICING_OPERATORS` as an array of dedicated staff identities, for example `{ "id":"owner", "token":"REPLACE_WITH_A_PRIVATE_43_CHARACTER_OR_LONGER_URL_SAFE_TOKEN", "applications":["simulation"], "permissions":["read","write","publish"] }`. Wrap the object in an array. This deliberately invalid placeholder must be replaced with a unique random value. The operator credential must differ from all application/identity credentials. Prefer one staff identity per person; rotating a token preserves its operator ID/audit history. The console is absent when the array is empty.

Keep port3100 loopback-only. Open `/v1/pricing` through an authorized local connection or SSH tunnel; do not expose it through the public simulation proxy. Enter the dedicated pricing token in the internal console. It remains in page memory and request headers, not browser storage or HTML. Application/identity service credentials never belong in that UI. Read-only, edit and publish permissions and application scopes are enforced on the server; no body role/actor is trusted.

Enter current costs, actual currency/conversion, per-unit support and price. Automatic calculations run on Credits; inspect losses, margin and monthly fixed-cost coverage. Costs may be fractional; settlement prices stay exact CNY fen. Save an immutable draft with evidence/source/date and expiry, then explicitly publish a reference price. A market adjustment creates another revision; previous snapshots remain. Compare-and-swap and idempotency prevent competing staff changes/retries from silently overwriting history. The recent50 revisions are listed in the console; all historical rows remain in the database backup.

For Simulation's price display add a separate catalog-only service credential under the existing company issuer/application, with `permissions:["catalog"]`; it cannot provision/close wallets or use the operator console. Set Simulation's `MODEL_LAB_CATALOG_URL=http://127.0.0.1:3100` and its private `MODEL_LAB_CATALOG_TOKEN`. The app reads only published metadata for `simulation:modeler-v1-local`, with a bounded ten-second server cache, without a frontend deploy. Draft versions never affect the visible reference price. Keep a product's billing type stable; use a separate product for a different billing arrangement.

Publishing reference prices and calculator eligibility do not enable real checkout, recurring collection, entitlement issuance or supplier execution. The current DTO explicitly says commerceEnabled:false. Existing cost/labor/margin review flags missing/expired/below-policy evidence. The calculator accepts loss-making scenarios so the owner can compare strategies; a later actual paid quote/order must enforce current approved funding and cost policy. Full quote/payment/refund/fulfillment and live operator access remain separate gates.

Backup the pricing_products, pricing_versions, pricing_actions and pricing_publications tables with the same stopped/consistent MySQL operational backup, including financial history. Do not roll a live price database back to undo a marketing decision: explicitly publish a reviewed existing/new version and retain the publication audit.
