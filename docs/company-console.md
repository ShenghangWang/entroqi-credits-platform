Back up existing company data before migrations, then run `npm run db:migrate` and `npm run company:register` using the private environment for that database. Migration000013 adds `company_application_products` without modifying financial history. It refuses unknown app records or changed mappings rather than deleting, relabeling or merging them. An existing incompatible namespace requires a reviewed explicit migration. ## Staff access

`CREDITS_PLATFORM_OPERATORS` is a JSON array of `{id,token,applications}`. Each ID must be unique and stable for its staff identity; each token must be a dedicated43–128character URL-safe random credential, distinct from product/authority credentials. Each scope must be one of the three registered applications. Example shape: `[{"id":"company-owner","token":"GENERATE_A_PRIVATE_TOKEN","applications":["simulation","atlas-simulation","atlas-ai"]}]`. The short placeholder deliberately fails validation; generate the real secret privately. An empty array leaves the console/routes absent.

Run `npm ci --ignore-scripts`, `npm run install:console` and `npm run build` from the Credits root, then set `CREDITS_CONSOLE_DIRECTORY` to the absolute `back-office/dist` directory for local service startup. This is the original Vue/Naive UI/ECharts console, including the original sidebar, tables, line/bar/pie charts and Developer/Admin/Agent components. `/back-office` serves it; `/` and `/v1/platform` redirect there. The earlier replacement panel was removed. The owner authorized the frontend source to be public on 4 November 2026. It is maintained in this same repository. The Docker image includes the compiled console at `/app/back-office/dist`; the operator credentials and writable staff-state directory are supplied privately at runtime.

Open `/back-office` on loopback. Use the configured operator ID and its dedicated token at the original login screen. Login exchanges that credential for a30-minute opaque HttpOnly/SameSiteStrict cookie; restart or logout revokes the session. No long-lived token enters browser storage or HTML. Use `CREDITS_CONSOLE_ORIGINS` for the exact trusted console origins; cross-origin session mutations fail. Staff roles come only from configuration, never the login body. An operator may optionally specify `role:developer|admin|agent`; omitted means developer. Agent configuration additionally requires its verified company `subject`. Retain private network access; this local session bridge is not a hosted SSO rollout.

The original dashboards and customer/wallet/ledger tables read the actual company-scoped identities, app memberships, wallets and transactions. Totals and hourly31-day trends use database aggregates; freeze events never count twice as settled consumption. Ledger consumer bars/function distribution and customer spending summaries use actual scoped settled transactions. Customer lists are bounded to1,000 rows and recent transactions to50; the ledger supports explicit pagination. Plan charts show empty states until real purchased-plan data is integrated. No former-employer totals, plan percentages or users are copied or simulated in the demo database.

Regular product users can self-register through the company authority without an agent. Preserve the original optional agent UI, policy helpers, approval/relation/commission core services and tests. `CREDITS_AGENT_WORKFLOWS_ENABLED=false` is the default, disables agent sessions and controls, and does not affect self-registration. An enabled agent can only read its approved referred-customer scope; it cannot use the broad bearer-token staff data API. Existing staff role permissions do not grant product purchases.

The original creation, approval, password, adjustment and settlement forms are retained. Their mutations explicitly return `INTEGRATION_NOT_ACTIVATED` until the owning company identity, audit and merchant/settlement integrations are connected. No second customer password database or legacy money/payment HTTP route is revived. The console is usable locally for dashboards/read review; retained write controls do not imply live payments or complete hosted account administration.

`GET /v1/platform/data?section=overview|customers|transactions|prices` remains a private credential-scoped metadata API for non-agent staff. No caller-selected application or role broadens it. Interactive pricing and the existing calculator now live at `/back-office/pricing` in this same original layout/session. `/v1/pricing` redirects there. Explicit `pricingPermissions` on staff control read/write/publication; no second local pricing token is needed. The optional legacy machine pricing API remains available only when separately configured. Credentials are never transferred by URL.

## Developer lockout and credential recovery

Use `CREDITS_PLATFORM_OPERATORS_FILE` for an authoritative owner-only JSON credential document (legacy array or versioned envelope), initialized from the existing operator configuration. In file mode, the file replaces the environment array completely: every login, session-authorized request and broad staff bearer request reads current credentials. Atomic rotations invalidate the changed operator's old credential and sessions across instances on their next request. File loss, unsafe permissions or malformed data deny access; old environment tokens never become fallback passwords. Do not mount one file inode into containers: mount its private parent directory read-only so atomic replacements are visible. App service and pricing credentials remain separate and unchanged.

`npm run staff:credentials -- recover` is available only to an independently authorized server/secret-store administrator, requires no forgotten developer credential, preserves the existing account's ID/role/app scopes, and writes a new random256-bit credential to a new private staging file. Requested/completed audit events contain the incident reason and OS actor, never the credential. There is no default recovery password or email-to-admin promotion. A separately verified email-and-offline-code recovery flow is available after explicit enrollment; [setup](owner-email-recovery.md). A local socket-IP login limit adds20 attempts/minute per process; ingress must provide deployment-wide controls. Read the complete [developer recovery runbook](developer-account-recovery.md) before public staff access.

The original login now provides a recovery-help link and `/back-office/recovery`; the sidebar opens the same help. Optional `CREDITS_COMPANY_ACCOUNT_RECOVERY_URL` points to the existing company account UI/Better Auth reset, not a new Credits password database. It is unconfigured locally pending a verified company URL. The separate owner recovery address is privately staged as unverified; no email sender is configured. Company password reset does not alter Credits developer grants or recover a separate operator credential. External recovery alerts, a staffed verified contact process and staff SSO/MFA still require launch configuration.

## Product integration

An app credential with catalog permission may read `GET /v1/application`, with no caller-supplied app parameter. It returns the app's registered issuer, product/catalog/access keys, website path, price product code and explicit `commerceEnabled:false,paidAccessEnabled:false`. Customer provisioning/balance/unlink remain the existing strict authenticated `/v1/customer` contract. Published prices are app-scoped via `/v1/catalog/<product-code>`. Pricing staff are separately configured with `CREDITS_PRICING_OPERATORS`; scope them explicitly to all three products as needed. Pricing product selection accepts only a catalog identifier, never a credential. Atlas price inputs stay blank until staff choose a price/unit.

Both Atlases use their backend-only adapter in the Atlas repository and resolve the company session before customer access. Same-origin hosted session wiring, product profiles/roles, actual checkout/refunds, entitlement issuance and protected paid content are not activated by this registration. The identity fixture in local integration evidence is explicitly a fixture, while Credits HTTP/MySQL are real. A shared wallet, positive balance, app membership or price is never accepted as paid access.
